# Architecture

## 0.10.1 editor presentation

TraxosFormPanel is now a full-screen surface; actual Dialog windows retain their own bounded presentation. This removes the previous floating frame from routed editors while preserving stable loading bounds and keyboard/scroll handling. FLAG_SECURE is applied only outside DEBUG; debug captures are explicitly enabled for UI review. Gift detail data/security contracts are unchanged; presentation is consolidated into one full-width panel.

## 0.10.0 recurring execution and interaction ownership

Account-owned recurring rules use indexed Room due reads and explicit schema9→10 migration. Ledger mutation and occurrence advancement are one database transaction using deterministic per-rule/date UUIDs. A private ledger repository avoids lock inversion against UI writes; worker retries retain idempotence. Local unique WorkManager jobs perform bounded batches. Invalid references retain due dates and surface errors. Account Transfer is now a dialog rather than a NavHost route; Undo stays in root feedback. Forms have fixed bounded frames; dialog windows suppress inherited animation. Native phone smoothness remains a device gate. See RECURRING_COMPACT.md.

## 0.9.2 entry presentation

Account/transaction/gift/card editors share a bounded centered surface; reusable selection/review sheets now use centered native Dialog windows with the existing custom content and no bottom-sheet slide. New-account card opt-in navigates only after successful account persistence and removes the new-account route. BANK debit references share the encrypted card vault without changing bank accounting. RecordRow has a nullable query-only Recorded timestamp projected from the indexed immutable journal; no entity/schema change or inferred payment timestamp.

## 0.9.0 encrypted card reference extension

Optional `account_card_secrets` is keyed by financial account ID with a restrictive foreign key. Only CREDIT_CARD accounts can store encrypted metadata. Android Keystore AES-GCM cipher uses a dedicated key namespace and row-bound associated data. No secret journal or saved-state persistence. Dedicated route-scoped editor uses single-flight saves and revision/operation checks; normal account lists never decrypt credentials. Existing ledger remains the source of card debt. Schema8→9 creates only this table. See COMPACT_PERSONAL.md.

Current implementation is 0.6.0: see [the current guide](UX_SMART_ENTRY.md) and the 0.6 section below. Earlier milestone sections document the evolution and are not current completion claims.

## Boundary and dependency direction

One Gradle app module to fit an 8 GB laptop; Kotlin packages isolate domain, data and UI. Compose → lifecycle ViewModel → repository → Room DAO. Manual constructor DI in Application; no global UI database access. Room Flow is the only finance read source. Navigation Compose owns destinations; SavedStateHandle owns form/operation identity and search state. No internet permission or cloud SDK in M1.

## Money and local schema

Money = checked signed Long minor units + ISO currency; parse through BigDecimal with UNNECESSARY rounding. No currency Float/Double. Bound amounts/row count to guarantee SQLite SUM remains within signed 64-bit limits, and check resulting account balances transactionally. Currency-specific fractional scales. Accounts: stable UUID, local profile, CASH/BANK type, currency, immutable opening balance, archive state and revision. Categories: seeded labels (not fake financial records), type. Transactions: UUID, account/category FKs, positive minor amount, EXPENSE/INCOME type, epoch day, timezone ID, note, revision and tombstone. Preferences singleton: theme, center shortcut and amount visibility. Journal: operation primary key, entity ID/type, base/local revision, kind, payload version, immutable payload, timestamp, pending state. Every financial/account mutation and journal entry commit together; operation identity is generated before submission and reused on retry. Account opening amount is journaled. Delete/Undo use tombstone/restoration events. Duplicate operation returns without a second mutation.

Amounts limited to 999,999,999.99 for 2-decimal currencies, 1 million transaction rows maximum per device in M1; aggregate worst-case stays below Long overflow. Account currencies are not converted or summed together. SQL computes balances and monthly summaries; indexed and paged ledger. No destructive migration fallback; exported schemas v1 and v2 tracked in Git; future changes require explicit migration and migration-test fixture before version increment.

## Screens and state

Home has month spending/income and per-currency account balance plus recent six rows, honest local-only status and Quick Add. Transactions is Room Paging 3 with debounced search; add/edit form validates amount, account/category, date/note. Accounts supports cash/bank create, rename, archive/restore (archive blocks new posts). Settings has persisted System/Light/Dark, configurable center shortcut, amount masking and version/data-loss explanation. Navigation preserves tab state; forms retain inputs and immutable operation ID in SavedStateHandle. Discard confirmation on dirty Back; commit gate disables actions synchronously. UI reports commit failure without clearing form; cancellation propagates. Material accessible controls, scrollable IME-aware form, full money values, ellipsized titles with editable full text.

Mixed-section Home LazyColumn keys are namespaced by section and stable identity; currency summary and balance rows must never share a key. Populated-state Compose rendering and persisted-ledger Activity launch/recreation are tested on the host in addition to repository math.

## Future extensibility (contracts, not implemented features)

Add paired postings for transfer/card settlement, linked refund/debt/group source payment and exact share allocations in M2. Existing expense/income cannot be relabeled as a settlement. Extend schema via tested forward migrations; do not shoehorn transfers into income/expense. Financial corrections preserve journal history and base revisions. Local profile namespace is reserved; account switching must isolate all rows/caches/work.

Optional backup uses streaming versioned canonical data + maintained KDF/AEAD, portable passphrase-derived key separate from Keystore. SAF outside app storage, preview/staging validation/atomic activation, safe merge/conflict review. User-owned Drive stores encrypted snapshots; upload acknowledgment alone is not a verified restore. Personal multi-device replication is a separate future decision, not an implied benefit of snapshot backup.

Future WorkManager schedules unique authenticated network-constrained work only after opt-in. A single profile lease drains dependency-ordered 100-op/256 KiB initial batches with stable IDs; ack transaction then pull opaque cursor pages transactionally. Retain unsent journal and tombstones; money conflicts need review, never blind last-write-wins. Server authorizes memberships/entitlements independently. FCM is only a hint, not financial source of truth. Firebase starts only with shared groups. No headless fake worker that claims to sync before a transport exists.

## Security boundary

M1 Room is app-private, not SQLCipher encrypted and has no PIN/biometric claim. Disable OS backup and explicitly exclude database/preferences/keys in cloud and device transfer rules pending tested recovery. FLAG_SECURE protects task previews in development; revisit accessible screenshot policy in M3. No sensitive logging or network/analytics. M3 must integrate maintained database encryption and Keystore envelope keys with invalidation recovery, supported BiometricPrompt and throttled slow PIN verifier. No custom cryptographic algorithms. Portable backup keys must work on another device. Never expose admin secrets in APK.

## 0.2.0 UI pass

Finance scope remains cash/bank accounts and expense/income CRUD. New packages/files separate custom components (`Components.kt`), dashboard (`Dashboard.kt`), financial lists (`LedgerScreens.kt`), compact chrome (`Navigation.kt`) and settings (`SettingsScreen.kt`); `App.kt` owns navigation/state/forms. Native vector icons use one line weight; the original five-square mark remains the brand motif. No added font, image, cloud or animation SDK.

Home reads existing SQL summaries and balances. Hero totals are separated by currency and include all recorded accounts (including archived), matching previous financial semantics. Active cards exclude archived accounts. Monthly inflow/outflow use recorded income/expense only. Empty data shows no invented monetary balance. Shared MoneyText masks amounts across Home, account cards and transaction lists; notes/names and entry/edit fields are intentionally not masked. Masking is a display preference, not encryption or authentication.

Room version 2 adds only `preferences.centerAction TEXT NOT NULL DEFAULT 'ADD_TRANSACTION'` and `preferences.balancesHidden INTEGER NOT NULL DEFAULT 0` using explicit MIGRATION_1_2. All financial entities and journal remain unchanged. Tests create a database from the shipped v1 schema, seed historical data and identity hash, and let real Room validate the upgrade. Column-specific SQL updates prevent changing theme from resetting shortcut/privacy. UI waits for preferences before showing dashboard totals, so a stored hidden preference cannot briefly show a visible default during startup.

Root tabs preserve Navigation Compose save/restore/singleTop behavior. Default NavHost crossfades were the observed outgoing/incoming text merge: all enter/exit/pop transitions now explicitly None. Every route has an opaque full-size surface. Selection/ripple/haptic feedback is limited to controls. Tests inspect the active page at 64ms after tab changes, inside the former fade duration. Settings remains top-right; bottom also offers direct Settings access with the three finance destinations and a separate configurable center action. Bar content is approximately 60dp at normal font scale, plus required system insets, versus the previous Material 80dp bar. Larger fonts can grow the chrome for accessibility.

Static, non-shimmer skeletons represent genuine Room/preferences loading: dashboard hero/metrics, account cards, ledger rows (initial paging or append), and form fields. Cached Ready data is used directly when changing tabs; skeletons are not a navigation animation. Save progress remains inline. Preference successes update the selected state and provide a haptic/saving indication instead of an obstructing snackbar; errors and financial Save/Delete Undo retain snackbars. Search focuses the existing debounced local ledger field. Quick Add remains available from the header even if the center action is reassigned.

## 0.4.0 gift wallet

`gifts/` owns rules/parser, Room entities/DAO, repository, Keystore envelope, transient ViewModel, bundled image recognition and WorkManager scheduling. `GiftWalletScreens.kt` and `GiftImportSettings.kt` reuse Traxos controls for wallet, detail/history, forms, import confirmation and preferences. Existing ledger tables/algorithms are not repurposed. Database v4 creates gift_cards, gift_redemptions, gift_settings and gift_notifications through explicit 3→4 migration; v1→2→3 upgrades remain supported.

Gift codes, PINs, notes and optional JPEG attachments share a bounded encrypted payload (AES-GCM, format byte + random 12-byte IV + authenticated ciphertext/tag), bound to the stable row ID as AAD. Attachments are bounded before encryption to avoid SQLite CursorWindow limits; selected images are bounds-decoded/downsampled off the UI thread. Keys are non-exportable Android Keystore AES/HMAC aliases. A normalized-code HMAC supplies a unique duplicate index, including archived cards; discount codes are scoped to merchant while stored-value and single-use cards share a scope. Deleted cards are tombstoned and leave the active duplicate index; deliberate re-entry after deletion is possible. Missing keys fail visibly; existing data never triggers a replacement key. The versioned payload is preparatory for future recovery, not portable backup. Metadata remains plaintext app-private Room; backup stays disabled.

Redemptions and last-redemption reversals update card state/history atomically with expected revisions and stable operation IDs. UI single-flight complements repository mutex and database uniqueness. Cards with history must use redemption/refund actions for balance changes, not form edits. Discount vouchers carry null values. Single-use vouchers require full use; stored-value partial use needs explicit user confirmation. Summaries exclude unknown, expired, archived and redeemed value and separate currencies. No gift operation writes cash/bank postings or the existing journal; acquisition and cash refund bookkeeping are explicit separate user ledger actions.

Imports originate only from user paste/share, image picker or native camera capture. Bundled ML Kit Latin OCR/barcode models are available offline; there is no SMS reading, link-following or model download. Uncertain fields remain blank. A custom editable confirmation precedes the full draft and explicit Save. Source text and plaintext drafts stay in memory, outside SavedStateHandle and saved instance state. Activity strips consumed share payloads from its intent; FLAG_SECURE continues to protect app previews. Revealed secrets clear on pause. Copy marks Android's clipboard sensitive and clears matching content after one minute; pasting is an explicit action. Review and Save are permanently required; automatic opening of the confirmation sheet is configurable. The merged manifest removes the internet permission inherited from ML Kit, preventing telemetry/network delivery.

WorkManager daily/startup/resume/mutation reconciliation schedules unique per-card/expiry/interval jobs for local 09:00 without exact alarms. Jobs recheck the current revision, preferences, redemption/archive/delete/expiry state and Android notification permission before posting generic text. Stable notification tags plus Room receipts deduplicate delivery across retries/restart. Date edits cancel old jobs; missed early reminders are skipped and overdue expiry can notify once. Actual delivery is subject to Android background restrictions. Jobs and Room metadata contain no code/PIN. Gift Cards and More are implemented optional slot destinations, with defaults kept unchanged and fallback Settings/More actions when absent.

## 0.7 UI review and root navigation

Main routes use stable content replacement with no saved child-stack restoration. Home explicitly pops to the existing Home root; Settings enters a fresh utility branch, and nested settings return to its homepage. Search/filter state stays in the lifecycle ViewModel. The isolated UI review route hides application chrome, owns a saved list of page IDs and resets at a fresh entry. Its composables accept metadata and callbacks only—no ledger/security/file/network service. Unsaved sample secret text is memory-only. Only the live destination registry enters configurable tabs; future pages remain explicitly labeled samples.

Appearance uses Room preferences and semantic Compose palettes; schema 7 adds accent with a conservative COBALT default via explicit 6→7 migration. All ledger/gift/inbox/journal entities are unchanged. Own-account transfers use the existing atomic operation journal and two linked TRANSFER_OUT/TRANSFER_IN records, matching currency, validated dates and active non-card accounts. Balance effect includes each leg; income/expense aggregation excludes them. Pair deletion and revision-checked Undo remain atomic. Shared SMS reference identity avoids counting opposite owned-transfer alerts twice. Gift-text amount scoring uses local contextual candidates, never network lookup or image OCR.

## 0.8 offline ledger tools

ActivityScope carries inclusive date bounds and optional account/category/currency IDs as primitive SavedStateHandle strings. MainViewModel combines debounced literal search, type, scope and Room-backed sort preference into cancelable Paging flows (40-row pages); filtering/sorting happen in SQLite. Deleted paging uses the same joins but ignores Activity scope and collapses linked movements to their outgoing leg. Restore calls the existing revision-checked atomic setDeleted/journal path and sends genuine Undo metadata. No permanent deletion/deletion-date fiction is introduced.

Monthly category aggregates are Room Flows over [first day, next month), grouped by category ID and original currency. Purchases/refunds/income are summed as Long independently; linked movements and tombstones are excluded. Report state has explicit Loading/Ready/Failed branches and retry. Category drill-through replaces Activity scope and retains a parent report back-stack entry. Utility entries from Settings return to their parent. All new screens use shared outlined Traxos controls. Schema8 adds only activitySort through 7→8; all financial entities stay unchanged.
